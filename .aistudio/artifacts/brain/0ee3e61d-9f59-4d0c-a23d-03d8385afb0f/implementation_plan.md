# 批量大盘「顶部同步横向滚动条」与「单场删除按钮」优化实施记录

针对用户在大盘表格模式下浏览多达 50+ 场赛事时提出的两大核心可用性痛点，已完成全面优化并构建验证。

---

## 1. 痛点问题分析

1. **只有底部才有横向滚动条**：
   - 当大盘队列包含 50+ 场赛事时，表格垂直高度可达数千像素。原生 `overflow-x-auto` 容器的横向滚动条默认贴在容器最下方（即第 50+ 场末尾）。
   - 处于表格顶部或中部的用户无法直接查看右侧被遮挡的盘口与操作列，必须先滚动到底部才能横向拖拽滚动条，体验极差。
2. **缺少场次删除按钮**：
   - 粘贴导入大量数据或 Markdown 时，常因源文本末尾附带的表头说明、调试信息等产生噪点行（如 `核 VS 探球赛事ID、同序球`、`及循环索引核 VS MatchTime`）。
   - 原界面每一行只有 `[变轨对比]`、`[锁定]`、`[复盘]`、`[研判 ➔]`，工具栏仅有「清空全部队列」，缺少单场移除按钮，导致无法剔除误导或异常数据。

---

## 2. 架构设计与技术实现

### A. 顶部常驻双向同步横向滚动条组件 (`SyncedTableWrapper`)
- **双向实时同步**：
  - 封装高复用 `SyncedTableWrapper` 容器，顶部挂载常驻横向滚动条，底部保留原生表格横向滚动条。
  - 使用双 `useRef`（`topScrollRef` 与 `tableContainerRef`）配合 `requestAnimationFrame` 锁，实现 1:1 双向像素级滚动位置无缝联动。
- **吸顶常驻 (`sticky top-0 z-20`) 与动态测宽**：
  - 顶部滚动控制栏采用 `sticky top-0 z-20 backdrop-blur` 设计，即使用户纵向滚动至第 30 场或第 50 场，横向滚动条与控制按钮始终悬浮在视窗顶部随手可用。
  - 通过 `ResizeObserver` 自动监听表格实际 `scrollWidth` 变化，使滚动滑块宽度与表格完全匹配。
- **快速横移与分栏跳端**：
  - 在顶部控制栏集成了方向微调按钮（`◀ 向左`、`向右 ▶`）以及快速锚点（`⏮ 对阵` 滑至首端、`研判/操作 ⏭` 滑至尾端）。
  - 全面支持 Flat 全量大盘表格与 Tiered 分层稳胆表格。

### B. 单场赛事删除与智能乱码清理
- **单行删除按钮**：
  - 在 `renderTableRow`（表格操作列）、`renderCardStreamItem`（卡片流）和 `renderSandboxStreamItem`（沙盘流）的操作按钮组尾端新增红色垃圾桶图标按钮（`Trash2`）。
  - 操作列最小宽度调整为 `min-w-[210px]`，确保所有功能按钮在同一行平整呈现，不产生错位折行。
- **状态同步与持久化**：
  - `App.tsx` 中定义 `handleDeleteBatchMatch(id)`，触发 `batchQueue` 过滤并由现存的 `useEffect` 自动同步至 `localStorage`。
  - 执行单场删除后触发优雅的通知条（`deleteToast`），实时反馈删除结果，支持手动关闭。
- **智能表头/乱码清理助手**：
  - 自动识别包含 `MatchTime`、`探球赛事ID`、`循环索引`、`同序球` 等典型导入噪点的场次。
  - 当检测到噪点时，工具栏即时呈现「清理乱码行 (X)」红色醒目操作入口，支持一键精准批处理净化。

## 3. 页面中段横向滚轮与交互全景强化

针对在 50+ 场长表格中间行时滚轮无法横向滚动、以及吸顶条在某些视口被隐藏的问题，做出了系统性升级：

1. **解决 Sticky 父容器失效隐患**：
   - 将外层包裹容器从 `overflow-hidden` 改为 `overflow-visible`，彻底消除了由于父级裁剪导致 `sticky` 定位失效的浏览器特性，确保顶部与底部吸附条始终在用户视口内有效。
2. **原生 MouseWheel 事件横向直转**：
   - 为表格容器挂载带有 `{ passive: false }` 的直接滚轮监听：
     - 原生横向滚轮 / 触摸板双指横推（`deltaX`）平滑直通。
     - 支持 `Shift + 滚轮` 加速横向滚动（倍率推进）。
     - 支持「滚轮转横向」快捷模式（顶部栏一键切换），开启后鼠标中键滚轮垂直转动直接驱动表格横向移动，到达边界时恢复纵向穿透。
3. **鼠标按住抓手平移拖拽 (Mouse Drag-to-Scroll)**：
   - 用户可按住鼠标左键在表格背景区域直接拖拽，实现类似画板/地图的平滑横向拖移，松开即停。
4. **视口底部悬浮吸附滚动条 (`sticky bottom-2 z-30`)**：
   - 在表格底部新增视口悬浮吸附滚动条与快速位移按钮，即使用户视口正好停留在表格中段（如第 20~35 场），不仅顶部有悬浮条，底部也始终有一条横向滚动条浮在屏幕下方，配合滚轮双保险。

## 4. 复盘模块支持识别 Markdown 文件 (.md / .txt)

针对复盘比分输入场景，全面支持结构化 Markdown 文档的自动识别与导入：

1. **文本与文件解析器升级 (`src/utils/textParser.ts`)**：
   - 过滤 Markdown 表格分割线（`|---|---|`、`|:---:|`）。
   - 保留并识别 Markdown 标题行中的比分（如 `### 曼城 2-1 埃弗顿`），移除开头的 `#` 前缀后正常提取主客队与比分。
   - 自动清洗 Markdown 列表符号（`-`、`*`、`+`、`1.`）、加粗符号（`**`）以及行内代码反引号（```），确保队名与比分干净利落。
2. **文件上传与拖拽注入 (`ReviewEvolutionView.tsx`)**：
   - 在复盘智能输入区新增 **「📁 上传 Markdown 文件 (.md/.txt)」** 按钮与隐藏式文件选择器。
   - 文本框区域支持全功能 **Drag & Drop (文件拖拽)**，拖入文件时高亮提示框体，松手即刻调用 `FileReader.readAsText` 自动提取。
   - 提取完成后提供即时反馈横幅，显示文件名、成功识别的比分场次数以及自动对齐待复盘队列的状态。

## 5. 开赛时间锁定引擎重构与多模态防误锁助手（解决“一次全部锁住”问题）

### A. 痛点与根本原因分析
1. **默认无参数 / 截止时间为空时全量误锁**：
   - 之前 `handleAutoLockStartedMatches` 在未传参或截止时间为空时，`else { shouldLock = true; }` 直接无条件锁定队列中所有比赛。
2. **空字符串与非结构化字符串导致比对失真**：
   - 采用 `mTime.localeCompare(cutoffTimeStr) <= 0` 进行文本比对。当比赛无开赛时间或为 `""` 时，`"".localeCompare(...) <= 0` 永远为 `true`，导致无时间场次全部被误锁。
3. **竞彩跨天销售周期时序颠倒**：
   - 足球比赛中，晚上 `23:00` 开赛的场次早于次日凌晨 `00:00`、`02:45` 开赛的场次。原字符串比对使 `"00:00" < "23:00"`，导致截止时间逻辑完全反向错乱。
4. **缺乏直观预览与场次列表核验**：
   - 旧弹窗仅有一个简单输入框，用户无法知道系统到底会锁哪些场次，误点后瞬间 42 场全部被锁，无法撤回。

### B. 技术解决方案
1. **竞彩销售日时序偏移计算 (`getSalesDayMinuteOffset`)**：
   - 以竞彩销售日 11:00 AM 为原点（0 分钟），`23:00` 为 720 分钟，次日 `00:00` 为 780 分钟，次日 `02:45` 为 945 分钟，实现跨午夜时序单调递增，彻底解决欧冠/五大联赛凌晨场次时序判定。
2. **精准时间结构化解析器 (`parseKickoffDetails` & `isMatchBeforeOrAtCutoff`)**：
   - 自动提取主客队、开赛小时与分钟、真实 UTC/北京时间毫秒时间戳 `kickoffTimestamp`，并与真实系统时刻对比判定 `isStarted`。
   - 无有效开赛时间或“临场”的场次严格判定为 `false`，绝不参与自动锁定。
3. **多模态智能锁定弹窗 (`BatchMatrixDashboard.tsx`)**：
   - **【🏷️ 按场次开赛时段选择】**：自动扫描当前大盘中真实存在的所有开赛时间段（如 `20:00 (5场)`、`23:00 (15场)`、`02:45 (8场)`），支持单选某个时段，或选择“早于或等于该时刻全部场次 (≤)”。
   - **【🕒 智能当前时间已开赛】**：依据客户端当前系统真实时刻，一键比对并仅锁定已过开赛时刻的比赛，未开赛比赛完全保持未锁。
   - **【⏱️ 自定义截止时刻】**：支持手动输入截止时刻，搭配快捷预设按钮。
4. **锁定结果实时核验预览 (Live Preview)**：
   - 弹窗底部实时高亮显示预计锁定的场次数与保留未锁的场次数，并支持展开查阅具体名单（对阵双方、联赛与开赛时间）。
   - 匹配为 0 场时锁定按钮自动禁用，杜绝误锁。
   - 执行锁定时，直接下发确定的目标场次 ID 集合，精准定向封盘。
