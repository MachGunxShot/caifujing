# 核心法则库「一键去重」优化实施方案

解决复盘法则库体检提示「检测到重复法则，建议一键去重」但在界面中缺失对应一键去重功能的问题。按照用户确认的去重策略，实现同场/同质法则的精准识别、最高印证记录保留与实战战绩样板无损合并。

## 用户确认与关键决策

> [!IMPORTANT]
> 经与用户确认，本次一键去重功能聚焦于**核心法则库体检提示的重复法则**，去重策略为：**保留最新或命中最高的一条，并合并战绩样板**。

- **去重目标模块**：`ReviewEvolutionView` 中的《财富经》核心法则库体系（对应 `rulesHealth.duplicateCount`）。
- **去重保留策略**：针对同场赛事来源（`cleanSource` 相同）或同标题核心规则，优先选取实战印证命中次数最高（`hitCount` 最大）且日期最新的法则作为母体，将重复子项中的实战对阵样板（`sourceMatch` 赛果样板）无缝汇流追加至母体，最后物理清理冗余副本。
- **健康度联动**：去重执行完毕后，法则库重复计数 `duplicateCount` 降为 0，即时消除体检警告并将健康度评分（Health Score）无扣分恢复。

## 1. 现状根因诊断

1. **体检提示与 UI 动作脱节**：
   - `experienceStore.ts` 的 `auditRulesHealth` 会精准扫描 `duplicateCount` 并在 `suggestions` 数组中输出：`检测到 X 处同场比赛重复法则（如单场生成两条），建议一键去重。`
   - 但在 `ReviewEvolutionView.tsx` 的治理工具栏（Governance Action Buttons）中，仅有「查漏补缺」、「智能聚类精炼」、「盘口观点自洽检修」和「清理零命中孤立个案」，**唯独缺少对应的「一键去重」实体按钮与函数**。
2. **聚类精炼未专职解决同场重复**：
   - 「一键智能聚类精炼」主要用于将单场碎片收敛回收至 7 大母本法则，对自定义/同场比赛衍生的多条重复项缺乏针对性的“保留最高印证、合并样板并清理冗余”的专门去重逻辑。

---

## 2. 界面交互与视觉设计

### A. 双触点交互设计
在用户界面中设置两个高度可见的操作入口，彻底解决“看到提示却找不到按钮”的痛点：
1. **体检建议警告栏（直接响应触点）**：
   - 当检测到 `duplicateCount > 0` 时，在体检建议框内重复法则提示项旁直接渲染 `[⚡ 立即一键去重]` 快捷按钮，支持一键就地修复。
2. **治理功能工具栏（常驻功能触点）**：
   - 在治理操作按钮组中新增专职按钮：`🧹 一键去重 (合并样板)`。
   - 当存在重复项时高亮标出重复数量（如 `(2处待处理)`），点击后立即执行合并与清理。

### B. 操作反馈与视觉体验
- **即时通知**：执行后弹出通知提示：`✅ 一键去重完成！成功清理并合并 X 处重复法则，已保留最高印证记录（最高命中 Y 次）并收纳实战战绩样板！`
- **体检仪表实时响应**：单场机械同质项卡片中的 `(X重复)` 红色警告标记立即消失，健康度分数恢复。

## 3. 技术架构与数据逻辑

```
┌─────────────────────────────────────────────────────────────┐
│                 ReviewEvolutionView (UI 层)                 │
│                                                             │
│   ┌─────────────────────────────────────────────────────┐   │
│   │ 体检建议框: "检测到 2 处重复法则" -> [⚡ 立即一键去重]  │   │
│   └─────────────────────────────────────────────────────┘   │
│   ┌─────────────────────────────────────────────────────┐   │
│   │ 治理工具栏: [🔄 查漏补缺] [🧹 一键去重] [✨ 聚类精炼]  │   │
│   └─────────────────────────────────────────────────────┘   │
└──────────────────────────────┬──────────────────────────────┘
                               │ 点击触发 handleDeduplicateRules
                               ▼
┌─────────────────────────────────────────────────────────────┐
│            experienceStore.ts (核心去重与合并引擎)           │
│                                                             │
│   1. deduplicateExperienceRules() 引擎                      │
│      - 归一化提取 sourceMatch 赛事标签与标题关键词          │
│      - 分组聚类: 找出重复组 (Count > 1)                     │
│      - 择优筛选: 优先选取 hitCount 最大且创建时间最新的条目 │
│      - 样板合并: 将所有重复项的实盘赛果切片追加至保留条目   │
│      - 物理移除: 清理被合并的重复副本                       │
│   2. saveExperienceRules() 持久化至 LocalStorage            │
│   3. 触发 auditRulesHealth() 实时重算健康度与体检指标       │
└─────────────────────────────────────────────────────────────┘
```

### 核心处理逻辑流程：
1. **识别键（Normalization Key）**：
   - 提取 `sourceMatch` 中过滤完场比分与空格后的核心对阵名；
   - 若无 `sourceMatch` 则结合 `title` 进行对阵提取。
2. **择优排序（Sorting Strategy）**：
   - 比较各重复候选：`(b.hitCount || 0) - (a.hitCount || 0) || b.createdAt.localeCompare(a.createdAt)`。
   - 选出胜者（Winner）。
3. **战绩样板合并（Battle Sample Merge）**：
   - 收集该组所有非空 `sourceMatch` 切片（以 `/` 分隔），通过去重 Set 提取唯一比赛对阵，并接驳至胜者的 `sourceMatch` 字段中。
4. **状态与存储同步**：
   - 写回 `localStorage`，刷新组件内的 `rules` 状态，触发 `useMemo` 重新运行 `auditRulesHealth`，消除警报。
